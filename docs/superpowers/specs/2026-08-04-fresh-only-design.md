# Только новинки: удаление архивной половины рекомендателя

Дата: 2026-08-04
Статус: дизайн утверждён владельцем

## Решение

Бот присылает только свежие релизы (не старше 7 дней, предзаказы не дальше
30). Архивная половина — «откопанное у соседей по вкусу» — удаляется целиком:
владелец попробовал её вживую и решил, что старые релизы ему не нужны.

## Что удаляется

| Что | Почему |
|---|---|
| `src/pipeline/archive.ts` + тесты | архивные кандидаты больше не собираются |
| `src/pipeline/neighbors.ts` + тесты | граф соседей нужен был только архиву |
| `src/bandcamp/collectors.ts` + тесты | единственный потребитель — граф соседей |
| `bin/neighbors.ts` | точка входа недельного пересчёта |
| `.github/workflows/neighbors-weekly.yml` | недельный джоб больше нечего считать |
| `data/neighbors.json` | данные пересчёта |
| `Candidate.neighborWeight`, `origin: 'archive'` | у кандидата остаётся один источник |
| Ветка «откопано у соседей» в карточке | объяснение архивного происхождения |

## Что меняется

- `select.ts`: `BucketSelection` — один `PoolOutcome` на бакет вместо пары
  fresh/archive. Кросс-пуловая дедупликация и исключение альтернатив другого
  пула убираются вместе со вторым пулом.
- `daily.ts`: до 4 карточек в день (по одной на канал), а не до 8.
- «🔄 Другой» перебирает только свежих кандидатов.
- `origin` у `Candidate` либо сужается до литерала `'fresh'`, либо убирается
  совсем — решается на этапе плана по фактическому числу мест использования.

## Что не меняется

Сбор свежака (Discover-хабы по тегам профиля + релизы 166 подписок), скоринг,
стоп-теги, hard-reject, штрафы за скипы, формат постов, апрув-кнопки,
ежедневный воркфлоу.

## Откат

Вся удалённая логика остаётся в истории git (ветка `main` до этого изменения);
возврат — revert коммита удаления плюс повторный запуск `bin/neighbors.ts`.
